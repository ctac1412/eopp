# Потеря логов при F5 во время выполнения

## Симптом

Usage log создается со статусом `pending`, но после F5 во время выполнения pipeline остается:

```text
status = pending
error_stage = null
error_message = null
logs = null
```

## Причина

Логи расширения во время выполнения живут в памяти content-script/Zustand. В БД они попадают только в финальных вызовах:

- `/confirm-usage`
- `/fail-usage`

При перезагрузке страницы срабатывает `beforeunload`, но текущий код вызывает async `reportFailure(...)` без гарантии завершения. Браузер может выгрузить страницу, content-script или port-соединение раньше, чем POST `/fail-usage` уйдет на сервер.

## Вариант решения

Сделать сохранение логов инкрементальным и устойчивым к выгрузке страницы:

1. Добавить endpoint для промежуточного сохранения логов, например `POST /usage-log/{id}/logs`.
2. В расширении периодически отправлять накопленные логи во время `running`:
   - при добавлении новых строк пачкой/debounce;
   - дополнительно после важных стадий pipeline;
   - без смены статуса записи.
3. На `pagehide`/`beforeunload` отправлять последний snapshot через `navigator.sendBeacon` или `fetch(..., { keepalive: true })`.
4. Финальный `/confirm-usage` и `/fail-usage` оставить как источник финального статуса, ошибки и последнего полного snapshot.

Минимальный быстрый вариант: добавить отдельный keepalive/beacon путь только для `beforeunload`. Надежнее: инкрементальный autosave плюс keepalive на выгрузке.
