# Сценарии счетов

## Ручной счет из журнала

`generate_invoice` используется, когда администратор выбирает подтвержденные, неоплаченные и еще не привязанные логи на вкладке "Журнал".

Поведение:
- создает обычный счет;
- привязывает выбранные `usage_log` к этому счету;
- оставляет записи неоплаченными до ручной отметки оплаты счета;
- после создания UI переводит администратора на вкладку "Счета" с фильтром по ID счета.

Этот сценарий нужен для разовых ручных счетов и логов, которые не должны попадать в авто-счет компании.

## Ручной счет со строками

`create_invoice` используется на вкладке "Счета" через кнопку "Новый счет".

Поведение:
- создает счет с произвольными строками `invoice_items`;
- не привязывает usage logs автоматически;
- подходит для ручных начислений, корректировок и внешних договоренностей.

## Авто-счет компании

Авто-счет - это один активный счет компании с `is_open = 1`.

Поведение:
- администратор создает авто-счет вручную на вкладке "Счета";
- подтвержденные usage logs компании автоматически привязываются к активному авто-счету;
- при фиксации авто-счета `is_open` выключается и счет получает обычный номер;
- следующий авто-счет создается только если для компании включено `auto_invoice_reopen`.

Термин "авто-счет" в UI используется вместо "открытый счет", чтобы не путать его с неоплаченным счетом.

## Предоплата

Предоплаченный пакет привязан к API ключу.

Поведение:
- при подтверждении usage log система сначала пытается списать цену из активного пакета;
- если баланс достаточный, usage log помечается оплаченным и не попадает в авто-счет;
- каждое списание пишется в `prepaid_deductions`;
- администратор может пополнить пакет и видеть журнал списаний на вкладке "Предоплата".
