# Распределённое решение капчи — технические требования

## Бизнес-цель

Ускорение решения icon-click капч путём параллельной работы нескольких участников: один **мастер** (владелец ключа) и один или несколько **операторов**. Каждый участник кликает своё подмножество иконок, общий прогресс виден всем в реальном времени.

---

## Роли

| Роль | `operator_id` | Описание |
|------|---------------|----------|
| Мастер | 0 | Владелец API-ключа. Может кликать любые иконки (включая операторские). |
| Оператор #N | 1, 2, ... | Помощник. Ограничен своим набором иконок. |

---

## Механика распределения

- Капча содержит 5 иконок (позиции 0–4)
- Иконки извлекаются из стрипа через `_extract_icons`, fallback — деление стрипа на 5 равных частей
- Мастер получает `assigned = [0, 1]`, оператор — `assigned = [3, 4]` (при 2 участниках)
- Каждый клик отправляется в `POST /distribution/answer`, возвращает следующую позицию
- Мастер (`operator_id == 0`) не ограничен: если доходит до чужой иконки раньше оператора — берёт её
- Операторы (`operator_id > 0`) ограничены своим `assigned`-набором. При попытке кликнуть чужую — 403

---

## Жизненный цикл капчи

```
┌──────────┐    клик    ┌──────────────────┐
│  Капча   │ ────────► │ /distribution/   │
│  создана │           │ answer           │
│  (SSE)   │           │                  │
└──────────┘           │ ┌─ next_pos = X  │──► след. иконка
                       │ └─ waiting: true │──► пауза (оператор закончил)
                       │ └─ complete: true│──► капча решена
                       └──────────────────┘
```

1. Сервер инициализирует `distribution_states[captcha_id]`
2. Мастер получает SSE `new_captcha` с `distribution.operator_id = 0`
3. Оператор получает SSE `new_captcha` с `distribution.operator_id = N`
4. Каждый клик → `POST /distribution/answer` → сервер возвращает:
   - `icon_position` — следующая позиция для клика
   - `image` — основное изображение (полное)
   - `icon` — изображение текущей иконки
   - `solved_count` — сколько своих иконок решил этот участник
   - `total_solved` — сколько всего иконок решено всеми
   - `answered_positions` — список решённых позиций (0–4)
5. После каждого клика сервер шлёт SSE `distribution_progress` всем — содержит `answered_positions`
6. Когда все 5 иконок решены — `captcha_solved` всем участникам

---

## Ответ `/distribution/answer`

```json
// Продолжение (есть ещё иконки):
{
  "icon_position": 1,
  "image": "base64...",
  "icon": "base64...",
  "total_icons": 5,
  "solved_count": 1,
  "total_solved": 2,
  "answered_positions": [0, 1]
}

// Оператор закончил свои, ждёт:
{
  "complete": true,
  "waiting": true,
  "solved_count": 2,
  "total_solved": 3,
  "total_icons": 5,
  "answered_positions": [0, 2, 3]
}

// Капча полностью решена:
{
  "complete": true,
  "coordinates": [{"x": 100, "y": 200}, ...],
  "answered_positions": [0, 1, 2, 3, 4]
}
```

## Состояния оператора

| Состояние | Описание | UI |
|-----------|----------|----|
| Не подключён | Выбор мастера | Форма с выпадашкой |
| Подключён | SSE открыт, ждёт капчу | Спиннер «Ожидание новой капчи...» |
| Активен | Решает иконки | Картинка + маркеры + иконка + точки |
| Пауза | Свои иконки решены, ждёт других | Спиннер «Ожидание...» |
| Решено | Капча полностью решена | «Капча решена, ожидание следующей...» |

---

## UI: маркеры на изображении

- Цветные нумерованные кружки (1–5) на позициях кликов
- Цвета: 1=красный, 2=оранжевый, 3=жёлтый, 4=зелёный, 5=синий
- Маркеры видны **всем участникам** локально (рисуются фронтом)
- Не накапливаются «чужие» маркеры — каждый видит только свои клики на изображении
- Прогресс **всех** участников отображается в точках-индикаторах (5 кружков):
  - Зелёный = решено (кем угодно)
  - Синий = текущая позиция
  - Серый = назначено, но ещё не решено
  - Тёмный = не назначено

## SSE события для распределения

| Событие | Кому | Описание |
|---------|------|----------|
| `new_captcha` + `distribution` | Мастер + операторы | Новая капча с распределением |
| `distribution_progress` | Всем (broadcast) | Обновление прогресса после любого клика |
| `captcha_solved` | Мастер + операторы | Капча полностью решена |

---

## Сохранение мастера у оператора

- Выбранный мастер сохраняется в `localStorage` (`operator_master`) и URL (`?master=<label>`)
- При F5 автоподключение к тому же мастеру
- API-ключи НЕ передаются оператору — только `id` и `label`

---

## Безопасность

- `GET /operators/{uuid}/masters` возвращает только `id` + `label` (не API-ключ)
- `POST /operators/{uuid}/link` принимает `master_id` (числовой), а не `master_key`
- Оператор НЕ может кликнуть чужую иконку (403, подсказка с `next_assigned`)
- Мастер может кликнуть любую (включая операторские) — ускорение
