# Оператор — бизнес-определение и назначение

## Определение

**Оператор** — это вспомогательный участник распределённого решения icon-click капч, работающий **параллельно** с мастером (владельцем API-ключа). Каждый оператор получает своё подмножество иконок капчи, кликает по ним и тем самым ускоряет общее решение.

Оператор **не владеет** API-ключом, **не платит** за использования и **не взаимодействует** с EOPP API напрямую. Он только помогает мастеру кликать иконки.

## Назначение

### Бизнес-цель

**Ускорение прохождения капч** на пропускных пунктах. Один мастер может физически не успеть кликнуть все 5 иконок за отведённое время (особенно при высокой нагрузке или медленном соединении). Один-два оператора сокращают время решения за счёт параллельной работы.

### Ключевые свойства

| Свойство | Значение |
|----------|----------|
| Идентификация | Уникальный UUID (12 hex-символов), числовой ID, читаемый nickname |
| Привязка | К одному или нескольким мастерам через `operator_master_links` |
| Права | Может кликать **только** иконки из своего `assigned`-набора |
| Видимость | Видит общий прогресс (какие позиции уже решены), но не видит API-ключ мастера |
| Срок жизни | Бессрочный, пока не удалён админом |
| Стоимость | Бесплатный — использования тарифицируются на мастере |

## Роли в распределённой системе

| Роль | `operator_id` | Права |
|------|---------------|-------|
| **Мастер** | 0 | Кликает любые иконки (включая операторские). Владелец ключа. |
| **Оператор #1** | 1 | Кликает только свой `assigned`-набор. Чужая иконка → 403. |
| **Оператор #2** | 2 | Аналогично, свой `assigned`-набор. |

## Карта распределения иконок

Иконок всегда 5 (позиции 0–4). Константа `DISTRIBUTION` задаёт, кому какие:

```python
DISTRIBUTION = {
    1: {"0": [0, 1, 2, 3, 4]},          # 1 участник = мастер делает всё сам
    2: {"0": [0, 1, 2], "1": [4, 3]},    # 2 участника: мастер 3 иконки, оператор 2
}
```

Схема для 2 участников: мастер идёт слева направо, оператор — справа налево, к центру:

```
Позиции:  [0]  [1]  [2]  [3]  [4]
Мастер:    →     →     →
Оператор:                     ←     ←
```

## Жизненный цикл оператора

```
 ┌──────────────┐
 │ 1. Создание   │  Админ создаёт оператора → генерируется UUID
 └──────┬───────┘
        ▼
 ┌──────────────┐
 │ 2. Выбор      │  Оператор открывает /operators/:uuid, выбирает мастера
 │    мастера    │  из выпадающего списка активных ключей
 └──────┬───────┘
        ▼
 ┌──────────────┐
 │ 3. Привязка   │  POST /operators/{uuid}/link → создаётся OperatorMasterLink
 └──────┬───────┘
        ▼
 ┌──────────────┐
 │ 4. SSE-поток  │  GET /operators/{uuid}/stream — постоянное соединение
 │              │  Ожидание капч от мастера
 └──────┬───────┘
        ▼
 ┌──────────────┐
 │ 5. Решение    │  Приходит new_captcha → получает assigned-иконки →
 │    капчи     │  кликает → POST /distribution/answer → следующая иконка
 └──────┬───────┘
        ▼
 ┌──────────────┐
 │ 6. Пауза /    │  Свои иконки кончились → waiting: true →
 │    Завершение │  ждёт мастера или берёт нераспределённые остатки
 └──────┬───────┘
        ▼
 ┌──────────────┐
 │ 7. Готово     │  captcha_solved → очистка, ожидание следующей
 └──────────────┘
```

## Состояния UI оператора

| Состояние | Триггер | Что видит |
|-----------|---------|-----------|
| **Не подключён** | Страница открыта, мастер не выбран | Форма с выбором мастера, кнопка «Подключиться» |
| **Ожидание** | SSE открыт, капчи нет | Спиннер «Ожидание новой капчи...» |
| **Активен** | Пришла капча с его иконками | Изображение капчи + текущая иконка + маркеры + индикатор прогресса (5 точек) |
| **Пауза** | Свои иконки решены, ждёт остальных | Спиннер «Ваши иконки пройдены, ожидание...» |
| **Решено** | captcha_solved | «Капча решена, ожидание следующей...» |

## Индикатор прогресса

5 точек под изображением, каждая соответствует позиции иконки (0–4):

| Цвет | Значение |
|------|----------|
| Зелёный (`#3fb950`) | Позиция решена (кем угодно) |
| Синий (`#58a6ff`) | Текущая позиция — эту иконку нужно кликнуть сейчас |
| Серый (`#6c757d`) | Назначено оператору, но ещё не решено |
| Тёмный (`#30363d`) | Не назначено этому оператору |

## Безопасность

- Оператор **не получает** API-ключ мастера — только числовой `master_id` и `label`
- `GET /operators/{uuid}/masters` возвращает только `id`, `label`, `active` (не `key`)
- Попытка кликнуть чужую иконку → **403** с указанием `next_assigned`
- Мастер (`operator_id == 0`) **не ограничен** — может кликнуть любую иконку, в том числе из набора оператора (ускорение)

## Хранение выбора мастера

- `localStorage` → ключ `operator_master`, внутри JSON `{ "<uuid>": { "id": N, "label": "..." } }`
- URL-параметр `?master=<label>` — для прямых ссылок
- При открытии страницы: сначала проверяется URL, потом localStorage, потом выпадающий список
- При F5 / перезагрузке — автоматическое переподключение к тому же мастеру

## Связанные сущности БД

| Таблица | Назначение |
|---------|-----------|
| `operators` | Сам оператор: id, uuid, nickname, created_at |
| `operator_master_links` | Связь оператор ↔ мастер: operator_id, master_key_id, active |
| `distribution_answers` | Ответы операторов: operator_id, icon_position, x, y |

## API

| Метод | Путь | Назначение |
|-------|------|-----------|
| `POST` | `/operators/{uuid}/link` | Привязать оператора к мастеру |
| `GET` | `/operators/{uuid}/masters` | Список доступных мастеров (id + label) |
| `GET` | `/operators/{uuid}/stream` | SSE-поток оператора |
| `POST` | `/distribution/answer` | Отправить клик по иконке |
| `POST` | `/admin/operators` | Админ: создать оператора |
| `GET` | `/admin/operators` | Админ: список операторов |
| `DELETE` | `/admin/operators/{id}` | Админ: удалить оператора |
