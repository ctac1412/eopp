### A.2 Убрать статус запланированного старта в футере
- [x] A.2.1 Убрать строку статуса запланированного старта (синяя полоса "Запуск через...") из футера модалки

### A.3 Общие настройки — 4-я колонка
- [x] A.3.1 В модалке в полноэкранном режиме вынести информацию с API-ключом и кнопку «Выйти» в отдельную 4-ю колонку «Общие настройки» (в ConfigForm grid), убрать из хедера

### A.4 Объединить injector_auth_key и injector_api_key

### A.5 admin_token из kiosk_api_key
- [x] A.5.1 `admin_token` для запросов к серверу брать из `kiosk_api_key` (localStorage `injector_api_key`), а не хардкодить

### A.6 Точность таймера до десятой доли секунды

## Агент B: Frontend + Backend — SSE, киоск, стримы

### B.1 SSE ошибки на UI
- [x] B.1.1 Выводить ошибки SSE-соединения на UI киоска: при разрыве стрима показывать уведомление/бейдж с текстом ошибки вместо ложного ощущения работы. Обновить `useSSE.js` + `App.jsx`/`StatusBar.jsx`

### B.2 Фиксированная высота лога в киоске
- [x] B.2.1 На странице киоска (вкладка "Капчи") сделать логи фиксированной высотой снизу; место под капчу не должно меняться динамически. Idle-спиннер и активная капча занимают одинаковую область.

### B.3 Кнопка логов в истории
- [x] B.3.1 На странице истории (`UsageHistory`) добавить кнопку "Логи" для каждого элемента, которая открывает сырые логи этого запуска (если доступны)

### B.4 Ограничение одного стрима на ключ
- [x] B.4.1 На бекенде (`src/routes.py`, `src/utils.py`) разрешить только 1 активное SSE-подключение на один `api_key`. При попытке второго подключения — разорвать старое и вернуть 429 клиенту. На фронте (`useSSE.js`) выводить ошибку "Другое подключение уже активно".
